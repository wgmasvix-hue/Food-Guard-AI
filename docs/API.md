# API Guide

The full interactive API reference is auto-generated by FastAPI from the Pydantic schemas and available at:

- Swagger UI: `{API_URL}/docs` (e.g. http://localhost:8000/api/v1/docs)
- ReDoc: `{API_URL}/redoc`
- OpenAPI JSON: `{API_URL}/openapi.json`

All endpoints are versioned under `/api/v1` and return JSON. Authenticated endpoints expect `Authorization: Bearer <access_token>`.

## Authentication flow

1. `POST /api/v1/auth/register` — creates a user (and a new company, if `company_name` is supplied) → returns the user.
2. `POST /api/v1/auth/login` — `{ email, password }` → `{ access_token, refresh_token }`.
3. `POST /api/v1/auth/refresh` — `{ refresh_token }` → a new token pair. The frontend does this automatically on a 401.
4. `POST /api/v1/auth/password-reset/request` / `/confirm` — email-based reset flow (token is logged to the API console when SMTP isn't configured).
5. `GET /api/v1/auth/me` — current user profile.

## Role-based access control

Every write endpoint declares a minimum role via `require_min_role(...)` (see `backend/app/core/rbac.py`). The hierarchy, low to high:

```
operator < auditor < production_supervisor < food_safety_officer < qa_manager < company_admin < super_admin
```

`super_admin` can act on any company; all other roles are scoped to their own `company_id` server-side, regardless of what a client sends.

## Automatic corrective actions

Some POST endpoints have side effects beyond creating their own record — when a value falls outside a defined limit, a `CorrectiveAction` is created automatically and linked back via `source` / `source_reference_id`:

- `POST /haccp/ccps/{ccp_id}/monitoring` — measured value outside `critical_limit_min`/`max` → `source: "ccp"`
- `POST /temperature/units/{unit_id}/logs` — temperature outside `min_temp`/`max_temp` → `source: "temperature"`
- `POST /gmp/checklists/{checklist_id}/submit` — a **critical** checklist item marked `fail` → `source: "gmp"`

## Rate limits

Global default: `RATE_LIMIT_PER_MINUTE` (120/min per IP). Auth endpoints (`/auth/register`, `/auth/login`, `/auth/password-reset/request`) use the tighter `AUTH_RATE_LIMIT_PER_MINUTE` (10/min per IP) to slow brute-force attempts.
